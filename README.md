# Контроль качества измерений в SQL

**dbt**-проект на PostgreSQL. Два исходных складских скрипта — как есть по логике запроса, с нейтральной предметкой: **контроль качества продукции**.

---

## Зачем это репозиторий

Проект отвечает на четыре практических вопроса:

1. Какие измерения массы оставить, если IQR-ограждение **меняется с возрастом**?
2. Какие строки отбраковать — выброс массы или неправдоподобный прирост (`LAG`)?
3. Что меняется, если возраст считать из дат, а не брать готовой колонкой?
4. Что меняется, если бин возраста — неделя (`/ 7`), а группы — линия × площадка?

Читать по номерам: `01` → `02`. Каждый `.sql` начинается с блока **«О документе»**.

---

## Как устроен проект

```text
.
├── README.md
├── dbt_project.yml
├── profiles.yml                    подключение к локальному PostgreSQL
├── models/
│   ├── 01_qc_kept.sql              скрипт 1: измерения внутри IQR
│   ├── 01_qc_outliers.sql          скрипт 1: отбраковка
│   ├── 02_qc_kept.sql              скрипт 2: недельный бин, возраст из колонки
│   ├── 02_qc_outliers.sql          скрипт 2: отбраковка (линия × площадка)
│   └── schema.yml
└── seeds/
    ├── items.csv                   паспорт изделия
    └── measurements.csv            масса по возрасту процесса
```

Два исходных SQL-скрипта, в каждом — две функции (оставить / отбраковать). В dbt это четыре модели.

## Что внутри моделей

| Файл | Вопрос | Данные | Методы |
|---|---|---|---|
| [`01_qc_kept.sql`](models/01_qc_kept.sql) | Какие измерения оставить при возрасте из дат? | [`seeds/measurements.csv`](seeds/measurements.csv), [`seeds/items.csv`](seeds/items.csv) | `LAG` прирост, `percentile_cont`, возрастной IQR |
| [`01_qc_outliers.sql`](models/01_qc_outliers.sql) | Какие строки отбраковать в том же контуре? | те же | тот же pipeline, инверсия WHERE |
| [`02_qc_kept.sql`](models/02_qc_kept.sql) | Что если возраст уже в таблице, бин = неделя? | те же | тот же IQR, бин `age_days / 7` |
| [`02_qc_outliers.sql`](models/02_qc_outliers.sql) | Как выглядят выбросы, если группа — линия × площадка? | те же | как в исходной outliers-функции скрипта 2 |

## Единый стиль

- SQL для PostgreSQL внутри dbt-моделей (`view`).
- Русские заголовки, английские имена таблиц и колонок.
- Логика запроса исходная: окна, вложенные подзапросы, `percentile_cont` с долей, которая зависит от бина.

Точечные правки, без которых PostgreSQL не выполняет скрипт 2: у подзапросов в `FROM` добавлены алиасы. Функции `breed_extract` / `sex_extract` заменены колонками паспорта — это смена предметки, не смена формулы IQR.

---

## Данные

Синтетические CSV в `seeds/`. Посажены spike массы, отрицательный прирост, повтор того же возраста и события `transfer`.

## Запуск

Нужен локальный PostgreSQL и база `sql_data_quality`. Параметры подключения — в `profiles.yml` или в переменных `DBT_HOST`, `DBT_PORT`, `DBT_USER`, `DBT_PASSWORD`, `DBT_DATABASE`.

```bash
createdb sql_data_quality
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export DBT_PROFILES_DIR=.
dbt debug
dbt seed
dbt run
dbt test
```

По умолчанию: `localhost:5432`, пользователь `postgres`, схема `analytics`.
